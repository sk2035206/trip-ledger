# H5 游玩计划

更新时间：2026-10-29。游玩计划已接入 H5，微信小程序界面留待后续同步。

## 只读分享（本地已完成，待发布）

在已保存的游玩计划右上角点击“分享计划”，可复制链接、使用系统分享或打开只读页。保存中、保存失败或存在冲突时，先完成保存再分享；没有创建计划时不提供分享入口。

- 地址为 `/play-plan/share?token=不透明分享令牌`，兼容 `/ledger/` 前缀；链接中不暴露出行 ID 或登录凭据。
- 持有链接者无需登录，即可查看该计划最新保存的每日安排、停留时间、交通说明、待选地点、地图点位与既定路线。已打开页面需刷新才能读取后续更新。
- 不提供编辑、排序、增删、搜索新地点、导入或导出入口；地图缩放、分类筛选、切换日期、定位已确认地点和生成既定路线仍可使用。
- 仅返回指定计划及出行标题、日期，不返回账本成员、费用、全量工作台数据或已从计划和待选移除的地点。计划内主动填写的备注和参考价格仍属于分享内容。
- 分享页路线接口仅允许计划中相邻站点已保存的步行、骑行、驾车路线，不开放任意地点搜索或任意路线查询。地铁、高铁和手动交通沿用原计划说明。
- 无已确认点位时，通过后端行政区接口定位当天城市，不调用高德 SDK 的 `setCity` JSONP 流程；仅允许查询计划中列出的城市。失败显示可重试提示，切换日期会取消旧查询，成功结果在当前页面缓存。
- 微信内点击分享入口先进入只读页，再使用右上角菜单；只读页注册自己的微信卡片标题与链接。系统分享被取消时不弹出错误。
- 无效令牌、已删除出行或不存在的计划显示不可访问；不会回退到默认示例。

接口：鉴权 `GET /api/trips/{tripId}/play-plan/share` 生成令牌；匿名 `GET /api/play-plan-shares/{token}` 读取单份计划；匿名地图子接口为该地址下的 `/maps/config`、`/maps/city` 和 `/maps/route`。分享接口只接受 GET。私有计划及工作台写接口继续要求原有登录。

令牌采用 AES-256-GCM 加密认证。本次不增加数据库表或字段。后端首次启动自动生成 `config/play-plan-share.json`（权限 0600），也可通过 `PLAY_PLAN_SHARE_SECRET` 配置 64 位十六进制随机值。此配置须保持 Git 忽略、发布归档排除，并在服务器升级和备份时保留；丢失或更换密钥、修改工作台密码都会使已有分享链接失效。目前没有单条链接撤销或有效期设置，持有链接者可继续查看，转发前应确认计划备注可分享。

匿名地图通过独立 HttpOnly 查看 Cookie 授权，Cookie 仅用于一级 `/_AMapService/` 白名单代理，不作为工作台登录凭据。分享页面禁止搜索引擎索引，并仅向地图服务发送来源域名而不携带令牌路径。

## 使用入口与启动

- 出行管理：每张出行卡片的“游玩计划”。
- 账单详情总览：“行前安排 / 游玩计划”卡片。
- 页面：`/play-plan?tripId=出行ID`，支持原有 `/ledger/` 部署前缀。
- 使用主项目 `npm run dev:start` 启动 H5 与 API；不需要启动 5180 独立原型服务。
- 当前本地 H5 地址为 `http://192.168.8.106:5173/`。更换网络后使用启动日志显示的新 IP。

首次打开某次出行时，可以填写城市和天数创建空计划、导入 JSON 攻略，或明确选择长沙 + 张家界示例。不同出行不会自动套用同一份攻略。

原独立页中的浏览器本地计划不会自动迁入数据库。可在原页面导出 JSON，然后在对应出行的游玩计划中导入。

## H5 功能

- 景点、美食、住宿、交通地点搜索；确认具体 POI 后落到地图上。
- 按天行程、待选收藏、地图联动、同日排序、跨天移动、每日主题/城市编辑与添加天数。
- “添加地点”弹窗提供“搜索新地点”和“从待选添加”；待选支持名称、城市、地址筛选，加入当天后保留收藏。
- “编辑安排”可改地点类型。类型属于地点本身，同一地点在其他日期和待选列表中同步更新；停留时间属于单次安排，各天分别保存。
- 交通方式：步行、骑行、驾车、地铁、高铁、手动交通。步行/骑行/驾车调用高德道路路线；地铁/高铁/手动交通记录实际线路、车次和时间说明，不伪造道路导航，也不计入道路合计。
- 计划停留时间为可选整数分钟，范围 0—1440；旧计划未填时保持“尚未安排”。卡片显示单站停留，底部合计已填写的停留时间，并在道路路线生成后显示已知交通 + 停留用时。未规划交通、候车、排队等不包含在合计内。
- JSON 导入导出包含类型、交通和停留时间，兼容之前缺少停留字段的计划。

## 数据与并发协议

新增 `trip_play_plans` 表：`trip_id` 主键，`plan_json` JSON 内容，`revision` 内容版本，以及创建/更新时间。所有表和字段有中文注释，不建立外键。原账本和费用表结构不变。

用户已明确确认新增计划表并使用数据库共享保存。当前配置对应数据库已完成该表初始化；初始化前后出行数均为 3，初始化时计划数为 0。浏览器创建/保存/冲突验收使用隔离的内存后端，没有向现有数据库写测试计划。

接口均复用工作台登录；也接受现有小程序的 X-Workbench-Session 协议，便于后续界面接入：

| 接口 | 行为 |
| --- | --- |
| GET /api/trips/{tripId}/play-plan | 返回 trip 元信息、plan 或 null、revision；没有计划时 revision 为 empty |
| PUT /api/trips/{tripId}/play-plan | 请求体为 plan 和读取时的 revision；成功返回新 revision |
| GET /api/maps/config | 仅返回 Web JS Key |
| GET /api/maps/city | city 对应行政区中心与缩放级别；服务端查询 |
| GET /api/maps/places | q、city 地点搜索 |
| GET /api/maps/route | origin、destination、mode；mode 为 walking / cycling / driving |
| GET /_AMapService/{path} | H5 一级安全代理，转发到受登录保护的地图 API |

保存时先锁定对应 trips 行，从而序列化首次创建与后续更新；版本不符返回 409，缺失版本返回 428，出行不存在返回 404。仅内容变化时写入，单纯 updatedAt 变化不改版本与数据库更新时间。

H5 将正在保存时的新编辑排队合并为最新草稿。网络失败保留草稿并提供手动重试；版本冲突停止写入，提示先导出草稿，再明确确认读取最新版，不自动刷新版本并覆盖其他设备。

出行被删除后，计划接口拒绝访问。当前未增加自动清理已删出行的历史计划行，保留在独立表中，避免此次接入改动账本保存事务；后续可单独确定清理策略。

## 高德配置与发布准备

- H5 使用 `config/amap.json` 或 AMAP_WEB_KEY / AMAP_SECURITY_CODE / AMAP_SERVICE_KEY 环境变量。
- 开发服务已禁止通过普通文件 URL 和 /@fs 路径读取 config 目录。
- 配置已按用户提供的值创建，Git 忽略；`config/amap.example.json` 仅有占位符。
- 安全密钥与 Web 服务 Key 仅在 Node 后端使用。公开接口只返回 Web JS Key。
- 发布归档包含复用界面的 modules/travel-guide/src 源码，并排除了 `config/amap.json`；部署时需在服务器单独配置，不把真实密钥放入归档。
- 高德 SDK 安全模式要求 `/_AMapService` 是一级 URL 路径。H5 用 `app/%5FAMapService/[...path]/route.ts` 提供同源转发，编码目录避免被 App Router 识别为私有目录。
- 若反向代理只将 `/ledger/` 转给 H5，应另加下列根路径代理。下列根路径代理已于 2026-10-29 部署到生产 nginx：

```nginx
location /_AMapService/ {
    proxy_pass http://127.0.0.1:5174/api/maps/_AMapService/;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

骑行使用高德 v4 `/direction/bicycling`，适配 errcode/data.paths 响应；步行和驾车沿用 v3。官方文档：https://lbs.amap.com/api/webservice/guide/api/direction 。
