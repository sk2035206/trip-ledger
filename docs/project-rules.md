# Trip Ledger 后续开发参考与约定

本文档记录本轮旅行分账项目沉淀下来的业务规则、技术限制和协作约定。后续任务开发应优先遵守本文档，除非用户明确提出新的调整。

## 1. 协作约定

- 用户没有明确说“部署”“发布到服务器”“上线”时，只更新本地代码，不上传服务器、不重启线上服务。
- 涉及数据库实际数据的新增、修改、删除、清理、迁移、修复前，必须先向用户说明影响并获得确认。
- 普通代码和 UI 调整可以直接本地实现；完成后运行必要验证。
- 发布到服务器时，只执行打包、上传、解压、重启和健康检查，不私自改数据库数据。

## 2. 项目定位

- 项目名称：Trip Ledger，旅行分账 H5。
- 当前形态：H5 Web 应用，后续可封装为 Android App。
- 主要用途：记录旅行账单、管理出行人员、录入公共费用/出行费用/个人费用，并生成最终分账清单。
- 当前访问域名：[https://jcxxy.cn/ledger/](https://jcxxy.cn/ledger/)。

## 3. 业务模块

### 3.1 首页工作台

- 首页是工作台，不直接进入某个账单。
- 首页分为全局数据和管理入口。
- 全局数据展示账单数、累计金额、公共费用、出行费用、人员库数量、类别数量等。
- 管理入口包括出行管理、人员管理、类别管理。

### 3.2 出行管理

- 用于管理旅行账单。
- 点击某个账单后进入该账单详情。
- 新建账单使用弹窗，不在列表页内展开表单。

### 3.3 人员管理

- 人员新增只能在人员管理中进行。
- 账单详情中的“本次人员”只能从全局人员库添加。
- 本次人员支持移除。
- 已被账单使用的全局人员不允许删除，避免历史账单失真。
- 账单详情页标签顺序中，“人员”放最后。

### 3.4 类别管理

- 类别用于公共费用分类。
- 类别新增使用弹窗。
- 已被公共费用使用的类别不允许删除。

## 4. 费用与计算规则

### 4.1 公共费用

- 公共费用是多人分摊的费用。
- 字段包括：事项名称、金额、类别、付款人、参与分摊人员、备注。
- 付款人默认是“公共付款”。
- 如果付款人为具体成员，则表示该成员已经支付该公共费用，最终结算时自动抵扣该成员应付金额。
- 成员付款不再单独录入“自付扣减”，避免同一笔费用双份数据。
- 公共费用计入公共总费用。
- 单项人均 = 单项金额 / 参与分摊人数。

### 4.2 出行费用

- 出行费用用于车票、机票、城际交通等。
- 出行费用按参与人员平均分摊。
- 出行费用独立统计，并计入对应成员最终合计。

### 4.3 个人费用

- 个人费用属于某个成员本人。
- 个人费用不参与分摊。
- 个人费用不计入公共总费用。
- 个人费用要计入该成员的最终合计。
- 分账清单中的成员“总计”列以当前计算逻辑为准，不额外新增总计行，避免重复理解。

### 4.4 成员付款

- 成员代付公共费用通过公共费用的“付款人”字段表达，最终结算时自动抵扣。
- 不再维护独立的自付扣减数据或 `adjustments` 表。

### 4.5 成员最终应付

成员最终应付金额：

```text
公共分摊 + 出行分摊 + 个人费用 - 已付款公共费用
```

其中：

- `已付款公共费用` 来自公共费用中付款人为该成员的金额。

## 5. 页面与交互规则

### 5.1 账单详情标签

账单详情页标签顺序：

```text
总览 / 清单 / 公费 / 出行 / 个人 / 人员
```

### 5.2 新增类操作

以下新增操作统一使用弹窗：

- 新建账单
- 新增人员
- 新增类别
- 新增公费
- 新增出行
- 新增个人费用

列表页只展示列表和新增按钮，不在列表中内嵌展开录入表单。

### 5.3 清单展示

- “公共费用明细”统一命名为“公共费用清单”。
- 公费、出行、个人清单使用紧凑卡片展示。
- 第一行展示费用名称，右侧展示类型标签。
- 公共费用中，付款人和分摊人独立展示。
- 金额展示顺序：金额在前，人均/说明在后。
- 删除按钮保留在清单项右侧。

### 5.4 成员明细

- 总览或清单中点击成员时，应在当前账单内部展示成员明细。
- 不跳转到全局明细列表。
- 成员明细支持按费用类型/类别筛选统计。

## 6. 数据库规则

### 6.1 存储方式

- 当前使用 MySQL 持久化业务数据。
- 配置模板：`config/mysql.example.json`。
- 本地真实配置：`config/mysql.json`，不应提交敏感信息。

### 6.2 表设计约束

- 表和字段必须有中文注释。
- 新建表也必须添加表注释和字段注释。
- 业务数据保存采用事务内增量同步，禁止通过清空整表再插入的方式保存，避免时间字段失真。
- `created_at` 只表示首次创建时间；`updated_at` 只在记录字段实际变化时更新。
- 当前数据库表之间不使用外键约束。
- 当前数据库表之间不建立关联索引约束。
- 保留表自身必要约束，例如主键、唯一键。
- 不要私自改动数据库实际数据；需要变动必须先问用户。

### 6.3 现有业务表

主要业务表包括：

- `people`：全局人员库。
- `categories`：公共费用类别。
- `trips`：出行账本主表。
- `trip_members`：账本成员关联。
- `shared_expenses`：公共费用。
- `shared_expense_participants`：公共费用分摊人员。
- `travel_costs`：出行费用。
- `travel_cost_participants`：出行费用分摊人员。
- `personal_expenses`：个人费用。

## 7. 前后端结构

- `app/`：页面与前端路由。
- `frontend/`：共享类型、计算逻辑、示例数据、API 客户端。
- `server/`：Node API、服务层、MySQL 存储。
- `server/mysql/schema.sql`：手工初始化参考 SQL。
- `scripts/`：本地和生产启停、打包、上传脚本。

## 11. 微信分享

当前项目已接入微信分享卡片能力。

- 项目域名：`https://jcxxy.cn/ledger/`
- 微信签名接口：`https://jcxxy.cn/gzh/api/wechat/signature?url=...`
- 分享图：`public/share-card.png`
- 分享接入组件：`app/wechat-share.tsx`
- 出行详情分享页：`/share?tripId={tripId}`。
- 分享页只能展示指定出行账单数据，不提供新增、删除、编辑、保存入口。
- 分享页读取单账本只读接口：`GET /api/trips/{tripId}`，不要让分享页读取全量 `/api/state`。
- 主应用账单详情中的“分享账单”按钮生成当前账单的分享链接。
- 微信内点击“分享账单”时，必须跳转到 `/share?tripId={tripId}` 只读分享页，再由用户使用右上角菜单分享，避免分享出主应用根地址。
- 非微信环境支持系统分享；系统分享不可用时复制分享链接。
- 根布局不要注册全局默认微信 JS-SDK 分享数据，避免覆盖详情页和只读分享页的具体账单分享链接。

生产启动时需要保持：

```text
NEXT_PUBLIC_SITE_URL=https://jcxxy.cn/ledger/
NEXT_PUBLIC_WECHAT_SIGNATURE_URL=https://jcxxy.cn/gzh/api/wechat/signature
```
