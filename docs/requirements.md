# 旅行分账 H5 需求文档

本文档描述当前已实现的功能范围。文档与 `app/`、`frontend/`、`server/` 的实际实现保持一致；开发约定见 `docs/project-rules.md`。

## 1. 项目背景

本项目用于记录每次旅游的公共花销、出行人员、成员付款和个人费用，并自动生成最终费用分账清单。第一阶段以 H5 移动端为主要形态，优先满足日常旅行结束后的快速核算；后续可通过 Android 封装方案扩展为手机 App。

## 2. 项目目标

- 快速创建一次旅行账本。
- 录入旅行成员和费用项目。
- 自动按参与人员分摊公共费用。
- 支持成员代付公共费用，并在结算时自动抵扣。
- 支持个人费用清单，个人费用不计入公共总费用，但计入个人最终合计。
- 自动生成类似“费用明细 + 出行费用 + 费用总计 + 小组合计”的分账清单。
- 数据以 MySQL 为主存储，不使用浏览器本地缓存保存账本。

## 3. 核心概念

### 3.1 旅行账本

一次旅行对应一个账本，例如“2026秦皇岛游玩费用”“2026长沙-张家界游玩费用”。

字段：

- 旅行名称
- 日期范围
- 出行成员
- 公共费用
- 出行费用
- 个人费用清单

### 3.2 成员

字段：

- 姓名
- 备注/分组，后续可扩展

成员分为两层：

- 全局人员库：维护常用出行人员。
- 本次旅行成员：只能从全局人员库中选择添加，用于本次旅行分摊和个人费用归属。

规则：

- 人员新增、删除统一在人员管理中操作。
- 出行账单内不提供新建人员入口，只提供从人员库添加至本次列表。
- 本次人员列表支持移除成员，移除后该成员不再参与本次账单计算，其个人费用一并移除，并从各费用项的分摊人中剔除。
- 已被任意出行账单使用的全局人员不允许删除，避免历史账单失真。

### 3.3 公共费用

公共费用指需要被多人分摊的费用，例如酒店、餐饮、门票、打车、景区费用等。

字段：

- 事项名称
- 金额
- 分类
- 付款人，默认为“公共付款”
- 账单时间，可选
- 参与分摊人员
- 备注

规则：

- 公共费用计入公共总费用。
- 单项人均 = 单项金额 / 参与人数。
- 如果某项只有部分成员参与，只分摊给勾选成员。
- 付款人为具体成员时，表示该成员已代付这笔公共费用，最终结算时自动抵扣该成员应付金额。
- 付款人抵扣不改变公共费用总额，也不再单独录入“自付扣减”，避免同一笔费用产生双份数据。

### 3.4 费用类别

费用类别用于公共费用分类，例如酒店、吃玩、交通、门票、其他等。

规则：

- 类别在类别管理中统一维护。
- 公共费用录入时只能选择已有类别。
- 已经被费用明细使用的类别不允许删除。

### 3.5 出行费用

出行费用用于记录往返车票、机票、城际交通等。

字段：

- 行程名称
- 金额
- 参与人员
- 备注/公式说明

规则：

- 出行费用独立展示。
- 出行费用按参与人员平均分摊后计入个人最终合计。

### 3.6 个人费用清单

个人费用指某个成员自己的费用，例如单独购买的零食、个人票据、个人补充消费等。

字段：

- 所属成员
- 事项名称
- 金额
- 日期，可选
- 备注

规则：

- 个人费用不计入公共总费用。
- 个人费用会进入该成员的个人最终合计。
- 系统需要提供单独的个人费用清单，方便逐条追溯。

### 3.7 成员付款

用于处理某些公共费用已经由个别成员先行垫付的情况，最终统计该成员本次还需要出的钱时，需要减去这部分金额。

表达方式：

- 公共费用的“付款人”字段，默认“公共付款”。
- 付款人指定为某成员时，表示该成员已支付该笔公共费用。

规则：

- 成员付款只影响成员最终应付金额。
- 付款金额在成员清单中表现为一条负数的“已付款抵扣”记录。
- 付款不计入公共费用、出行费用、个人费用和统计总额。
- 付款不改变公共费用总额。
- 不额外维护独立的自付扣减数据或 `adjustments` 表。

### 3.8 成员最终应付

```text
成员最终应付 = 公共分摊 + 出行分摊 + 个人费用 − 已付款公共费用
```

其中：

- `已付款公共费用` 来自公共费用中付款人为该成员的金额。

## 4. 计算规则

### 4.1 公共费用

- 公共费用总额 = 所有公共费用金额之和。
- 单项人均 = 单项金额 / 该项参与人数。
- 成员公共分摊 = 该成员参与的所有公共费用分摊金额之和。

### 4.2 出行费用

- 出行单项分摊 = 出行费用金额 / 该项参与人数。
- 成员出行合计 = 该成员参与的所有出行费用分摊金额之和。

### 4.3 成员最终合计

成员最终应付 = 成员公共分摊 + 成员出行合计 + 成员个人费用 − 成员已付款公共费用。

### 4.4 总额口径

- 公共总费用只统计公共费用。
- 出行费用单独统计。
- 个人费用单独统计，不混入公共总费用。
- 最终应付统计以成员个人合计为准。
- 分账清单中的成员“总计”列即上述成员最终应付，不额外新增总计行，避免重复理解。

## 5. 页面需求

### 5.1 首页工作台

- 首页定位为工作台，而不是单个账单详情。
- 第一块为全局数据：展示出行账单数量、累计金额、公共费用、出行费用、人员库数量等统计。
- 全局数据支持图表化展示金额构成。
- 第二块为管理类入口：出行管理、人员管理、类别管理。
- 从出行管理点击某个出行账单后，才进入该账单内的成员、费用和清单逻辑。

### 5.2 出行管理

- 展示所有出行账单列表。
- 支持新建出行账单，使用弹窗，不在列表页内展开表单。
- 每个账单展示名称、成员数量、费用项数量、当前合计。
- 点击账单进入该账单详情页。
- 提供账单金额分布统计。
- 账单内已存在费用记录时不允许删除，避免误删历史数据。

### 5.3 人员管理

- 维护全局人员库。
- 新增人员只能在人员管理中完成，使用弹窗。
- 展示人员参与过的出行账单数量。
- 未被账单使用的人员可删除。
- 账单详情中的本次人员只能从该人员库选择添加。

### 5.4 类别管理

- 维护公共费用类别。
- 新增类别使用弹窗。
- 展示类别被公共费用使用的次数。
- 未被使用的类别可删除。
- 公共费用录入使用类别管理中的类别选项。

### 5.5 账单总览

- 展示当前账单名称。
- 展示公共总费用、公共参考人均、出行费用、个人费用、已付款、成员数。
- 总览页统计卡片支持点击跳转到对应标签。
- 展示成员费用总计。
- 总览页点击成员时，在当前账单内部展示该成员明细，不跳转到全局清单。
- 成员明细支持按费用类型/类别统计，并展示柱状图。

### 5.6 本次人员

- 从全局人员库选择人员添加至本次账单。
- 本次人员列表支持移除。
- 不允许在本次人员页面新建人员。
- 账单详情页标签顺序中，“人员”放在最后。

### 5.7 公共费用录入

- 录入事项名称、金额、账单时间、分类、付款人。
- 勾选参与分摊人员，支持全选。
- 自动显示该项人均。
- 支持编辑和删除费用项。
- 支持按类别筛选清单。
- 支持多选费用项后批量调整分类和参与人员。

### 5.8 公共费用截图导入

- 支持选择账单截图，通过本地 OCR 识别文字。
- 支持直接粘贴或修改识别文本后重新解析。
- 解析结果生成待确认项目列表，展示事项、分类、金额、账单时间。
- 识别出的分类按关键词自动匹配类别管理中的选项，无法匹配时落到“其他”。
- 待确认项目支持逐条编辑、勾选/取消勾选、全选。
- 导入前统一勾选参与分摊人员。
- 确认后批量写入当前账单的公共费用清单。

### 5.9 出行费用录入

- 录入行程名称、金额、参与人员、备注。
- 自动按参与人员分摊。
- 独立生成出行费用清单，支持编辑和删除。

### 5.10 个人费用清单

- 选择成员。
- 录入个人费用事项、金额、日期和备注。
- 展示按成员归属的个人费用明细。
- 个人费用不进入公共总费用。

### 5.11 成员付款录入

- 通过公共费用的“付款人”字段选择成员，无需独立录入页面。
- 默认“公共付款”表示无人垫付。
- 成员清单中展示每个成员的已付款抵扣明细。

### 5.12 分账清单

- 展示公共费用清单：事项、分类、金额、人均。
- 展示出行费用清单：行程、金额、人均。
- 展示个人费用清单。
- 展示成员费用总计：人员、总计、出行、公共、个人、已付抵扣。
- 总览和分账清单中的人员支持点击进入个人费用明细。
- 个人费用明细支持按费用类型/类别统计和筛选：酒店、吃玩、交通、门票、出行、个人、已付款抵扣等。
- 支持选择多个成员计算小组合计，并展示该组合的分项统计。

### 5.13 账单分享

- 主应用账单详情提供“分享账单”按钮，生成当前账单的分享链接。
- 微信内点击“分享账单”跳转到只读分享页 `/share?tripId={tripId}`，再由用户使用右上角菜单分享，避免分享出主应用根地址。
- 分享页只展示指定账单数据，不提供新增、删除、编辑、保存入口。
- 分享页读取单账本只读接口，不读取全量状态接口。
- 分享页生成 Open Graph / Twitter 卡片元数据，展示账单名称、人数和合计金额。
- 微信内配置 JS-SDK 分享卡片标题、描述和缩略图。

### 5.14 页面路由

- 主应用使用浏览器 history 管理视图与标签切换，支持浏览器前进/后退。
- 账单详情支持通过 `?tripId={tripId}&tab={tab}` 直接打开指定账单和标签。

## 6. 第一阶段开发范围

- H5 移动端适配。
- 接入独立后端 API，前端通过 HTTP 读写账本数据。
- 后端接入 MySQL 存储，提供 `config/mysql.json` 配置连接信息。
- 浏览器不再保存账本数据，本阶段以 MySQL 后端为唯一数据源。
- 内置示例数据，参考用户提供的两张旅游费用清单。
- 完成成员、公共费用、出行费用、个人费用、分账清单功能。
- 完成公共费用截图 OCR 导入。
- 完成微信分享与只读分享页。
- 完成基础构建验证与单元测试。

## 7. 前后端代码边界

- 前端页面：`app/`，负责页面渲染、交互和调用后端 API。
- 前端共享模型与计算：`frontend/`，负责类型、示例数据、分账计算、截图文本解析和 API 客户端。
- 后端服务：`server/`，负责 HTTP API、业务服务、MySQL 连接、数据读写和建表。
- 后端 HTTP 层：`server/http/`，负责请求解析和 JSON 响应。
- 后端业务层：`server/services/`，负责组织账本读取、保存和存储健康检查。
- 后端数据层：`server/mysql/`，负责 MySQL 连接池、配置读取、业务表建表和关系表读写。
- 数据库配置：`config/mysql.json`，用于本地配置真实连接；`config/mysql.example.json` 作为模板。
- 数据表初始化脚本：`server/mysql/schema.sql`。
- 安全边界：后端 API 默认只监听 `127.0.0.1:5174`，局域网用户访问 H5 的同源 `/api/*` 代理，不直接暴露 MySQL 写接口端口。
- Next 路由层：`app/api/` 仅做同源代理，把请求转发到后端 API。
- 访问控制：当前按公开访问项目处理，`/api/state`、`/api/trips/{tripId}` 和 `/api/health` 不做口令校验；后续可根据业务补充登录体系。

## 8. 接口设计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 存储健康检查，返回存储类型、数据库、主机、端口和各业务表行数 |
| GET | `/api/state` | 读取全量状态：人员库、类别、所有出行账本 |
| PUT | `/api/state` | 保存全量状态，返回保存后的状态 |
| GET | `/api/trips/{tripId}` | 读取单个出行账本，供只读分享页使用 |
| GET | `/api/share-card.png` | 微信分享缩略图 |

## 9. 数据库存储设计

MySQL 按业务域拆分为多张关系表，不保留旧版本整包 JSON 快照，也不使用 `adjustments` 自付扣减表。

- `people`：全局人员库。
- `categories`：公共费用类别。
- `trips`：出行账本主表。
- `trip_members`：出行账本与人员的关联表。
- `shared_expenses`：公共费用明细，含付款人和账单时间。
- `shared_expense_participants`：公共费用参与分摊人员。
- `travel_costs`：出行费用明细。
- `travel_cost_participants`：出行费用参与分摊人员。
- `personal_expenses`：个人费用清单。

数据读写流程：

1. API 入口根据路径分发请求。
2. HTTP 层解析请求并返回统一 JSON。
3. Service 层执行账本读取、账本保存、存储健康检查等业务动作。
4. Repository 层负责建表、事务保存和关系表聚合查询。
5. 保存账本时在事务内按主键增量同步新增、更新和删除，避免部分写入，同时保留记录创建时间。
