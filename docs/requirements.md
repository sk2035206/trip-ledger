# 旅行分账 H5 需求文档

## 1. 项目背景

本项目用于记录每次旅游的公共花销、出行人员、成员自付费用和个人费用，并自动生成最终费用分账清单。第一阶段以 H5 移动端为主要形态，优先满足日常旅行结束后的快速核算；后续可通过 Android 封装方案扩展为手机 App。

## 2. 项目目标

- 快速创建一次旅行账本。
- 录入旅行成员和费用项目。
- 自动按参与人员分摊公共费用。
- 支持成员自付扣减。
- 支持个人费用清单，个人费用不计入公共总费用，但计入个人最终合计。
- 自动生成类似“费用明细 + 出行费用 + 费用总计 + 小组合计”的分账清单。
- 第一版数据以 MySQL 为主存储，浏览器本地缓存作为后端不可用时的兜底。

## 3. 核心概念

### 3.1 旅行账本

一次旅行对应一个账本，例如“2026秦皇岛游玩费用”“2026长沙-张家界游玩费用”。

字段：

- 旅行名称
- 日期范围
- 出行成员
- 公共费用
- 出行费用
- 个人费用清单
- 自付扣减

### 3.2 成员

字段：

- 姓名
- 备注/分组，后续可扩展

成员分为两层：

- 全局人员库：维护常用出行人员。
- 本次旅行成员：只能从全局人员库中选择添加，用于本次旅行分摊和个人费用归属。

规则：

- 人员新增、删除统一在人员管理中操作。
- 出行账单内不提供新建人员入口，只提供从人员库添加至本次列表。
- 本次人员列表支持移除成员，移除后该成员不再参与本次账单计算。
- 已被任意出行账单使用的全局人员不允许删除，避免历史账单失真。

### 3.3 公共费用

公共费用指需要被多人分摊的费用，例如酒店、餐饮、门票、打车、景区费用等。

字段：

- 事项名称
- 金额
- 分类
- 参与分摊人员
- 备注

规则：

- 公共费用计入公共总费用。
- 单项人均 = 单项金额 / 参与人数。
- 如果某项只有部分成员参与，只分摊给勾选成员。

### 3.4 费用类别

费用类别用于公共费用分类，例如酒店、吃玩、交通、门票、其他等。

规则：

- 类别在类别管理中统一维护。
- 公共费用录入时只能选择已有类别。
- 已经被费用明细使用的类别不允许删除。

### 3.5 出行费用

出行费用用于记录往返车票、机票、城际交通等。

字段：

- 行程名称
- 金额
- 参与人员
- 备注/公式说明

规则：

- 出行费用独立展示。
- 出行费用按参与人员平均分摊后计入个人最终合计。

### 3.6 个人费用清单

个人费用指某个成员自己的费用，例如单独购买的零食、个人票据、个人补充消费等。

字段：

- 所属成员
- 事项名称
- 金额
- 日期，可选
- 备注

规则：

- 个人费用不计入公共总费用。
- 个人费用会进入该成员的个人最终合计。
- 系统需要提供单独的个人费用清单，方便逐条追溯。

### 3.7 自付扣减

用于处理某些项目已经由个别成员自行支付，最终统计该成员本次还需要出的钱时，需要减去这部分金额。

字段：

- 所属成员
- 自付说明
- 自付金额
- 备注

规则：

- 自付金额只影响成员最终应付金额。
- 金额通常为负数，表示该成员已经支付过一部分费用，需要从最终应付中扣减。
- 自付不计入公共费用、出行费用、个人费用和统计总额。
- 自付不改变公共费用总额。

## 4. 计算规则

### 4.1 公共费用

- 公共费用总额 = 所有公共费用金额之和。
- 单项人均 = 单项金额 / 该项参与人数。
- 成员公共分摊 = 该成员参与的所有公共费用分摊金额之和。

### 4.2 出行费用

- 出行单项分摊 = 出行费用金额 / 该项参与人数。
- 成员出行合计 = 该成员参与的所有出行费用分摊金额之和。

### 4.3 个人最终合计

成员最终应付 = 成员公共分摊 + 成员出行合计 + 成员个人费用 + 成员自付扣减。

### 4.4 总额口径

- 公共总费用只统计公共费用。
- 出行费用单独统计。
- 个人费用单独统计，不混入公共总费用。
- 最终应付统计以成员个人合计为准。

## 5. 页面需求

### 5.1 首页工作台

- 首页定位为工作台，而不是单个账单详情。
- 第一块为全局数据：展示出行账单数量、累计金额、公共费用、出行费用、人员库数量、类别数量等统计。
- 全局数据支持图表化展示金额构成。
- 第二块为管理类入口：出行管理、人员管理、类别管理。
- 从出行管理点击某个出行账单后，才进入该账单内的成员、费用和清单逻辑。

### 5.2 出行管理

- 展示所有出行账单列表。
- 支持新建出行账单。
- 每个账单展示名称、成员数量、费用项数量、当前合计。
- 点击账单进入该账单详情页。
- 提供账单金额分布统计。

### 5.3 人员管理

- 维护全局人员库。
- 新增人员只能在人员管理中完成。
- 展示人员参与过的出行账单数量。
- 未被账单使用的人员可删除。
- 账单详情中的本次人员只能从该人员库选择添加。

### 5.4 类别管理

- 维护公共费用类别。
- 展示类别被公共费用使用的次数。
- 未被使用的类别可删除。
- 公共费用录入使用类别管理中的类别选项。

### 5.5 账单总览

- 展示当前账单名称。
- 展示公共总费用、出行费用、个人费用、自付扣减、成员数、人均参考。
- 展示成员费用总计。
- 总览页点击成员时，在当前账单内部展示该成员明细，不跳转到全局清单。
- 成员明细支持按类型/类别统计，并根据场景展示饼图或柱状图。

### 5.6 本次人员

- 从全局人员库选择人员添加至本次账单。
- 本次人员列表支持移除。
- 不允许在本次人员页面新建人员。

### 5.7 公共费用录入

- 录入事项名称、金额、分类。
- 勾选参与分摊人员。
- 自动显示该项人均。
- 支持删除费用项。

### 5.8 出行费用录入

- 录入行程名称、金额、参与人员、备注。
- 自动按参与人员分摊。
- 独立生成出行费用清单。

### 5.9 个人费用清单

- 选择成员。
- 录入个人费用事项和金额。
- 展示按成员归属的个人费用明细。
- 个人费用不进入公共总费用。

### 5.10 自付扣减

- 选择成员。
- 录入自付说明和扣减金额。
- 主要支持负数扣减。
- 展示每个成员的自付明细。

### 5.11 分账清单

- 展示公共费用明细：事项、分类、金额、人均。
- 展示出行费用明细：行程、金额、人均。
- 展示个人费用清单。
- 展示成员费用总计：人员、总计、出行、公共、个人费用、自付。
- 总览和分账清单中的人员支持点击进入个人费用明细。
- 个人费用明细支持按费用类型统计和筛选：酒店、吃玩、交通、门票、出行、个人、自付等。
- 支持选择多个成员计算小组合计。
- 支持复制文字版清单。

## 6. 第一阶段开发范围

- H5 移动端适配。
- 接入独立后端 API，前端通过 HTTP 读写账本数据。
- 后端接入 MySQL 存储，提供 `config/mysql.json` 配置连接信息。
- 浏览器不再保存账本数据，本阶段以 MySQL 后端为唯一数据源。
- 内置示例数据，参考用户提供的两张旅游费用清单。
- 完成成员、公共费用、出行费用、个人费用、分账清单功能。
- 完成基础构建验证。

## 7. 前后端代码边界

- 前端页面：`app/`，负责页面渲染、交互和调用后端 API。
- 前端共享模型与计算：`frontend/`，负责类型、示例数据、分账计算和 API 客户端。
- 后端服务：`server/`，负责 HTTP API、业务服务、MySQL 连接、数据读写和建表。
- 后端 HTTP 层：`server/http/`，负责请求解析和 JSON 响应。
- 后端业务层：`server/services/`，负责组织账本读取、保存和存储健康检查。
- 后端数据层：`server/mysql/`，负责 MySQL 连接池、配置读取、业务表建表和关系表读写。
- 数据库配置：`config/mysql.json`，用于本地配置真实连接；`config/mysql.example.json` 作为模板。
- 数据表初始化脚本：`server/mysql/schema.sql`。
- 安全边界：后端 API 默认只监听 `127.0.0.1:5174`，局域网用户访问 H5 的同源 `/api/*` 代理，不直接暴露 MySQL 写接口端口。
- 访问控制：当前按公开访问项目处理，`/api/state` 和 `/api/health` 不做口令校验；后续可根据业务补充登录体系。

## 8. 数据库存储设计

MySQL 按业务域拆分为多张关系表，不再保留旧版本整包 JSON 快照。

- `people`：全局人员库。
- `categories`：公共费用类别。
- `trips`：出行账本主表。
- `trip_members`：出行账本与人员的关联表。
- `shared_expenses`：公共费用明细。
- `shared_expense_participants`：公共费用参与分摊人员。
- `travel_costs`：出行费用明细。
- `travel_cost_participants`：出行费用参与分摊人员。
- `personal_expenses`：个人费用清单。

数据读写流程：

1. API 入口根据路径分发请求。
2. HTTP 层解析请求并返回统一 JSON。
3. Service 层执行账本读取、账本保存、存储健康检查等业务动作。
4. Repository 层负责建表、事务保存和关系表聚合查询。
5. 保存账本时在事务内按主键增量同步新增、更新和删除，避免部分写入，同时保留记录创建时间。
