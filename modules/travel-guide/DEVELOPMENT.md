## 3. 第一版功能范围

### P0：必须完成

1. 展示旅行标题、目的地、5 天日程和来源提示。
2. 切换日期，地图仅显示当天点位，支持查看全程。
3. 高德关键词搜索，显式选择城市、具体分店/入口；展示名称、地址与分类。
4. 搜索结果可加入待选收藏或当天行程，支持景点、餐厅、酒店、交通四类。
5. 卡片点击定位地图；地图标记点击选择对应卡片，编号跟随顺序更新。
6. 删除、修改备注、同日排序、移动到另一天；鼠标拖动配合上下移动按钮，移动端和键盘也可操作。
7. 生成当天分段路线：步行、驾车；高铁/索道/环保车等标为手动段。
8. 切换日期、重排、修改点位或交通方式后，旧路线立即失效，避免显示错配结果。
9. 本地保存、刷新恢复、导出 JSON、校验后导入 JSON；导入覆盖前确认，失败不破坏现有数据。
10. 加载、空列表、地图失败、搜索失败、权限/额度错误、无路可走均有明确反馈。

### P1：第一版稳定后考虑

- 自动排序建议：固定酒店/车次，可预览、应用、撤销；不宣称全局最优。
- 每站停留时间与计划时刻，提示时间冲突。
- 跳转高德导航、附近地点、打印行程。
- 多次旅行管理、日期调整。

### 暂不做

AI 自动生成、PDF 自动解析、票务预订、酒店实时价格、实时协作、账户系统、云端保存、公交/城际自动规划、真实分账集成、旅游内容社区。

## 4. 页面与交互设计

采用清晰的旅行手账风格：浅暖背景、深绿主色、餐厅用暖橙、酒店用蓝色，保留充足留白。不要把地图作为背景装饰，不添加无法使用的操作按钮。

### 桌面

- 顶部：模块名称、旅行标题、保存状态、导入/导出。
- 日程区：日期导航、当日主题与地点列表；地点卡包含分类、备注、定位状态、调整操作。
- 地图区：占主要空间，当前日期/全程切换、分类筛选、地图缩放与适配点位。
- 待选地点：作为标签页或可收起区域，避免三栏同时挤压地图。
- 点位详情/搜索：弹窗或抽屉，不挤压主列表。

### 手机

- 顶部紧凑旅行信息，横向日期条。
- 地图与行程切换，或地图加底部可展开面板；首版选择一种完成。
- 搜索以全宽抽屉呈现；动作触控区域至少 44px。
- 筛选状态保留，底部操作不盖住地图版权信息。

### 地点确认流程

原攻略地点文字 → 选择正确城市 → 搜索 → 查看分店/入口和地址 → 确认具体 POI → 在地图标记。

禁止将首个搜索结果无提示地当作正确地点；禁止给未确认地点编造坐标。尚未确认的地点保留在时间线，显示“确认位置”，不参与真实路线规划。模糊品牌名不能当成精确分店。

### 路线流程

每一段交通方式属于“从上一站到本站”的连接，第一站不显示交通段。界面明确“按当前顺序生成路线”，不要与“自动优化顺序”混用。

- 未确认地点：指出缺失的站点并要求确认，不静默跳过后连接不相邻的站点。
- 手动段：仅展示交通说明；可选虚线必须标注“顺序示意，非导航路线”。
- 步行/驾车：向服务端请求每对相邻点的路线，绘制高德返回的道路折线。
- 某段失败：保留成功段并逐段说明失败；合计注明仅包含成功规划的路段。
- 总时间是交通时间，不含停留、候车、排队，不称作“今日总耗时”。
- 日期/顺序变化时取消请求或通过请求版本丢弃旧响应。

## 6. 推荐架构与模块隔离

为了后续接入现有 React 项目，建议正式开发采用 React + TypeScript + Vite 的独立前端，以及 Node HTTP 服务适配层。不引入 ORM、数据库或 Cloudflare 设施。

已有原始 JS 骨架可复用协议思路，允许改造成上述结构；它不是必须保留的技术决策。独立 package.json、独立依赖与锁文件，禁止无意修改根项目依赖。若新增 TS/TSX，需要检查根 tsconfig 的递归 include，必要时只增加该独立模块的 exclude，避免主项目误编译模块代码。

建议目录：

```text
modules/travel-guide/
  DEVELOPMENT.md
  README.md
  package.json
  config/example.json
  config/local.json              # 已忽略，真实密钥
  src/
    components/                 # 日程、地图、搜索、地点详情
    domain/                     # 类型、排序、路线段、数据校验
    adapters/                   # 高德、HTTP、本地存储
    data/                       # 历史攻略种子
  server/                       # 配置加载、受限高德代理、API
  tests/
```

地图组件只接受标准地点/路线和回调，不自己管理整个旅行；业务模型不依赖 AMap 对象。使用 MapAdapter 隔离地图创建、标记、折线、fitView、destroy。高德地图只在浏览器挂载，卸载后销毁。

以下是目标结构，当前 model.mjs 尚未实现完整模型：

路线结果单独保存为临时派生状态：相邻 stop ID、模式、distanceMeters、durationSeconds、polyline、status、error。缓存键包含两端坐标和交通方式；不把旧路线当成永久事实导出。

每个实例 ID 稳定且唯一；同一个地点可在多天重复出现。删除行程站点不应删除其他日期引用的地点。导入校验版本、枚举、有限坐标范围、字符串长度、数量上限、引用完整性及 ID 唯一性。恢复失败展示提示，不静默覆盖损坏数据。

## 8. 高德配置与接入

用户已提供 Web JS Key、安全密钥、Web 服务 Key，并授权写入配置。真实值已写入 `config/local.json`，不在本文重复。

| 配置字段 | 用途 | 浏览器可见性 |
| --- | --- | --- |
| webKey | 加载高德 JS API 2.0 | 可见，按高德控制台配置来源限制 |
| securityCode | 地图 JS 服务安全校验 | 仅服务端，在代理中追加 jscode |
| serviceKey | 搜索、步行/驾车 Web API | 仅服务端 |
| port | 独立本地服务端口，默认 5180 | 非秘密 |

- `config/local.json` 已加入根 `.gitignore`，权限设置为 0600。
- 示例配置只放占位符。不要复制密钥到 README、前端 bundle、日志、测试快照或错误响应。
- 配置集中加载并校验，未来可通过环境变量覆盖。缺失配置时给出不含密钥的清晰启动错误。
- 浏览器先获取公开 webKey，加载 JS API 前设置 `_AMapSecurityConfig.serviceHost = location.origin + '/_AMapService'`。
- 代理使用固定高德域名和允许的路径，禁止由用户传入任意目标 URL；Web API 参数显式白名单。
- 示例默认绑定 127.0.0.1；用户已要求局域网访问，本地配置 host 已设为 0.0.0.0，启动时打印实际 LAN 地址。若后续部署，补齐同源访问约束、代理接口速率限制和身份控制，避免作为公开配额代理。
- 高德坐标使用 GCJ-02；不要与 OSM/WGS84 混用。

官方参考：
- 安全代理：https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode
- JSAPI 示例：https://developer.amap.com/demo/list/js-api-v2
- Web 路线：https://lbs.amap.com/api/webservice/guide/api/direction
- 路线 2.0：https://lbs.amap.com/api/webservice/guide/api/newroute

现有骨架使用 v5/place/text 与 v3/direction/walking、v3/direction/driving。下一轮开发须实际验证这些 Key 对相应产品的权限、来源限制、额度和 API 返回字段，不得仅凭 Key 已配置声称接入成功。

## 9. 服务接口约定

| 接口 | 入参 | 返回/行为 |
| --- | --- | --- |
| GET /api/config | 无 | 仅 webKey，绝不返回另外两种密钥 |
| GET /api/places | q、city | 规范化 places：id、name、location、address、city、category |
| GET /api/route | origin、destination、mode | distance（米）、duration（秒）、points（经纬度数组） |
| GET /_AMapService/... | JS SDK 请求 | 受限同源代理，追加服务端 jscode |

坐标参数顺序为 lng,lat。路线 mode 仅允许 walking/driving；manual 不调用服务。错误统一 `{error: string}`，避免原样返回带密钥请求或异常栈。响应解析验证数值和折线，不把空路径当成功。

搜索通过用户提交触发，避免每次键入请求；分页和附近搜索放后续。路线请求按需生成，限制并发，设置超时与取消。初始页面不要自动批量查询全部景点，避免误定位和无必要配额消耗。
