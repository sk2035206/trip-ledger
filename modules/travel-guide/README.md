# 山水之间 · 独立旅行攻略模块

基于 React、TypeScript、Vite 和 Node HTTP 的独立原型，初始内容为长沙 + 张家界五日游。独立入口的行程保存在当前浏览器；H5 已原生复用该页面，按出行存入数据库并复用工作台登录，详见 ../../docs/play-plan.md。

## 启动

需要 Node.js >= 22.13.0。在仓库根目录执行：

```bash
npm ci --prefix modules/travel-guide
npm run dev --prefix modules/travel-guide
```

访问 http://127.0.0.1:5180/ 。终端按 Ctrl+C 停止服务。

本地使用构建产物：

```bash
npm run build --prefix modules/travel-guide
npm start --prefix modules/travel-guide
```

开发模式与产物模式使用同一个端口，先停止前一个进程再切换。可用 `TRAVEL_GUIDE_PORT=5181` 覆盖端口。Vite、依赖和锁文件均位于本模块，主项目仅增加类型检查和构建目录隔离规则。

## 局域网访问

当前本地配置已开启局域网监听，普通 `dev` / `start` 命令也支持局域网。也可以显式运行：

```bash
npm run dev:lan --prefix modules/travel-guide
# 或使用构建产物
npm run start:lan --prefix modules/travel-guide
```

启动日志会打印当前网卡的 LAN 地址，例如 `http://192.168.8.106:5180/`。手机与电脑连接同一个局域网后，用日志里的地址访问；更换网络后以新日志为准。若系统弹出本地网络/防火墙提示，允许 Node 接收入站连接。

通过 IP 打开与 localhost 属于不同浏览器存储来源；如需转移当前计划，先在原地址导出，再在新地址导入。手机 HTTP 页面已兼容不提供 `crypto.randomUUID` 的浏览器环境。高德来源限制如已开启，需要包含实际使用的访问来源。

## 配置

真实高德配置在 `config/local.json`，已写入用户提供的值，Git 忽略且权限为 0600。新机器可参考 `config/example.json` 创建。也支持环境变量：

- `AMAP_WEB_KEY`：Web JS Key，唯一允许返回给浏览器的配置。
- `AMAP_SECURITY_CODE`：安全密钥，通过同源地图代理使用。
- `AMAP_SERVICE_KEY`：服务端地点搜索和路线请求使用。
- `TRAVEL_GUIDE_PORT`：默认 5180。
- `TRAVEL_GUIDE_HOST`：覆盖监听地址；`config/local.json` 的 `host` 已按用户要求设为 `0.0.0.0`，允许局域网访问。示例配置仍默认仅本机。

不要将真实配置加入版本库。开发服务已禁止直接访问配置和服务端文件；本模块尚未作为公开互联网服务加固，不应直接对外开放。

## 使用方式

1. 在日期条切换每日安排；最后一天预留为空白。
2. 对原攻略地点点“确认位置”，选择搜索城市并提交关键词，核对分店或景区入口后确认；未确认地点不绘制地图标记。
3. 搜索新地点可“加入当天”或“存入待选”；待选地点可再次加入任一天。
4. 点击卡片定位地图，点击标记选中相应卡片。地图可看当天或全程，支持四类地点筛选。
5. 拖动把手或用上下按钮调整顺序；“编辑安排”可改备注、交通方式、移动到另一天或移除站点。
6. “生成路线”按现有顺序逐段请求步行/驾车路线。高铁、索道、环保车选“手动交通”，填写说明。
7. 编辑后自动保存到此浏览器。导出 JSON 可备份或迁移；导入文件校验通过且确认替换后才应用。

路线合计只包括成功的道路段，不含游览、排队、候车和手动交通。修改行程或换日会清除旧路线。分类筛选、待选页和全程视图隐藏当日道路折线，避免把部分地点误当完整路线。

历史攻略中的酒店价格、车次与预约提示均需出行前核实。饭店品牌、景区名称未自动选择首个搜索结果；浏览器验收已覆盖景点、酒店和饭店点位。临时测试安排已通过导出备份恢复，未修改原始种子数据。

## 工程结构

- `src/domain/`：旅行模型、导入校验、排序、跨天移动和路线分段。
- `src/data/seed.ts`：原攻略的未确认地点与美食备选。
- `src/adapters/`：本地存储、HTTP、高德地图、可取消的路线规划。
- `src/components/`：地图、搜索弹窗、站点卡片和原生 dialog。
- `server/api.mjs`：受限高德 API 适配，支持注入 fetch 进行离线测试。
- `server.mjs`：配置加载、同源 API、开发/产物服务。
- `tests/`：模型、导入、存储、过期路线隔离、服务参数与响应测试。

集成现有项目时，可复用业务模型和组件，替换 PlanRepository 与 HTTP 路径；具体规划见 [开发方案](./DEVELOPMENT.md)。
